# CLAUDE.md

This repo holds the code, configs and paper figures for our tabular foundation model project. The model is a
transformer over rows and columns pretrained on synthetic tables and evaluated on a benchmark of 51 real
classification and regression datasets. Please read all of this before doing anything!!

## Layout

- src/tfm/ the package (model.py, prior.py for the synthetic table generator, train.py, eval.py)
- configs/ yaml configs, base.yaml is canonical
- benchmark/ the evaluation harness, benchmark/score.py is the scorer of record
- figures/ one folder per paper figure, panel scripts inside
- paper/ the LaTeX source
- runs/ is gitignored and lives on the cluster

## Environment

Always use the conda env `tfm` with python 3.11. Set PYTHONNOUSERSITE=1 or packages from ~/.local shadow the env.
Torch 2.5 with CUDA 12.1. Never pip install into base. If something is missing ask me, don't install it.

## Rules for code

Use type hints on every public function. Docstrings with a short example. Keep functions under about 60 lines.
Never leave commented-out code. No print debugging left in committed code, use the logger. Ruff must pass before a
commit. Tests live in tests/ and must run on CPU in under 3 minutes: PYTHONNOUSERSITE=1 pytest tests/ -q.
Don't add a new dependency without asking me. Prefer numpy and torch, no pandas in the training path (it was a
bottleneck, 3x slower data loading).

## Configs

base.yaml is canonical. Never reason from the dataclass defaults in config.py, they drifted from the yaml at least
twice. When you add a config key, also add it to the list in scripts/launch.sh, otherwise the cluster jobs silently
use the default (this happened in March and cost a week).

## Experiments

Every run gets its own TAG and output folder, never reuse a TAG. Three seeds per arm minimum. Report the mean and
the seed standard deviation. A difference smaller than two seed SDs is noise, don't call it an improvement. Write
the decision criteria for a comparison before the results come in. Never compare a run trained for fewer steps to
one trained for more without saying so.

## SUPERSEDED (Feb): use the old prior

We used to train on prior v1 only. SUPERSEDED: prior v2 is now the default since the April ablation. Kept here for
reference. Prior v1 had a bug in the categorical column sampler (it never produced more than 8 categories).

## Benchmark

benchmark/score.py is the scorer of record. Never edit it without asking. The benchmark has 51 datasets (as of
June; check benchmark/datasets.csv for the current count). Use the fixed splits in benchmark/splits/, never resplit.
Report ranks per dataset and the mean rank, plus wins/ties/losses against each baseline with the paired test in
benchmark/stats.py (Wilcoxon, BH correction). Our current mean rank is 2.1 (check before quoting!).

## Figures

Figures use the style in figures/style.py. Helvetica, 7 pt for labels, 6 pt ticks, 180 mm wide for full width.
Every panel script writes a pdf and a png. No titles on panels, the caption carries it. Colors for methods come
from figures/palette.py, never hard-code a hex. Look at the rendered png before saying a figure is done.

## Writing

Plain sentences. No em dashes. No "not X but Y". No words like powerful, seamless, novel, leverage. Numbers in the
paper must come from the result files, never typed by hand, paper/numbers.tex is generated by
scripts/make_numbers.py.

## SUPERSEDED (May): always use 5 seeds

We said 5 seeds for everything in May, then went back to 3 because of compute. Ignore this block.

## Git

Commit in small logical commits. No Claude attribution lines in commit messages. Never force push. Never commit
anything from runs/ or data/. Don't push unless I say so.

## Working with me

Don't ask me about routine choices, decide and write it in NOTES.md. Ask before deleting anything, before spending
more than 50 GPU hours, and before changing the benchmark. When I say "update docs", go through NOTES.md and fold
lessons into this file and the guidelines. Keep final messages short: what changed, where the files are, what I
need to decide.

## Cluster

Jobs go through scripts/launch.sh, one job per seed, no job arrays (not allowed on our cluster). Check the queue
before submitting. Name jobs tfm-<tag>-<seed>. Logs go to runs/<tag>/logs/. A job that exits 75 was requeued and
resumes by itself from ckpt.pt, don't resubmit it.
