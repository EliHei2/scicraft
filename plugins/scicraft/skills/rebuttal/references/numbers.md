# Numbers and quotations

Reviewers check replies against the PDF line by line, and one was expected to do it with a language model. A single
wrong number or misquotation costs more than any argument gains. Every check below runs on every build.

## Numbers asserted against records

The pattern that worked: a check script inside the build asserts every number the prose states against the record
file it comes from, so restructuring the prose cannot break it and a refit cannot leave a stale sentence behind.
The build prints "prose numbers match the records" or stops. Tables are generated by scripts from the records and
never typed by hand.

`check_numbers.py --claims claims.json` is the general form. Each claim names where the number appears, its value,
the record and the path into it:

```json
[{"where": "reply R1, W1", "value": "2.10", "file": "results/bench.json", "key": "methods.ours.mean_rank"},
 {"where": "reply R1, W2", "value": -0.05, "file": "results/ablations.csv", "row": {"ablation": "no_context"}, "column": "delta"},
 {"where": "abstract", "value": 9, "file": "results/bench.json", "key": "n_tasks_first",
  "prose": "source/abstract.tex", "text": "ranks first on 9 of 14 tasks"}]
```

- The tolerance defaults to half a unit of the last printed decimal ("2.10" accepts 2.095 to 2.105; write a value with trailing zeros as a string, since JSON drops them). Give `tol`
  for a rating printed as an integer.
- With `prose` and `text`, the sentence piece must still be in the file, so a sentence edited away is caught.
- Add a claim for every number you add to the text, at the moment you add it.
- Run a control build with nothing changed after new records arrive, to see whether a rebuilt upstream file moved
  an asserted number.

Stale numbers in the source work came from older drafts and from co-authors' documents written against an earlier
method set: ranks one place off, a count of comparators from before a method was added, a mean computed over the
wrong grouping. Tell co-authors when their document cites an older count.

## Every number in a reply is printed in the paper

`check_numbers.py --trace replies.md --paper paper.txt` lists every number in the replies that the paper text does
not print. Quoted reviewer lines and pointers (lines, Table, Figure, Appendix, Section, Eq.) are skipped; list
numbers and counts of reviewers go in `--ignore`. The rule behind it: a reviewer must be able to find each number in
the revised PDF.

## Printed values and recomputes

- **Never replace a printed value by a recompute, and never weaken a printed win.** A recompute that differed from
  the printed value in the third decimal was reverted to the print. If a recompute differs, keep the print and tell the author.
- Never turn a non-significant result into a significant one, and never print a number the records do not hold.
- Print bounds as the paper does ("< .01", never ".008" for .0085). Keep 6 decimals in data files, since rounding
  twice changes the third decimal.
- Reproduce any new statistic locally with the same code and records as the paper, so a new p value in a reply is
  exact and checkable. Doing this once found that a set of tables used a different multiple-testing correction from
  the one the paper states.
- Never call a reviewer's number wrong when it is your own table's number: "tell only part of these results", never
  "do not match".

Statistics wording (one correction everywhere, "significant" defined once, no confidence intervals by default, how
to report ranks and ratings) belongs to the `stats-reporting` skill.

## Quotations

`check_replies.py --sources reviews.md paper.txt guideline.txt` matches every double-quoted passage of five or more
characters, and every quoted line (`>`), against the source texts after normalizing whitespace and curly quotes. An
ellipsis splits a quote into parts checked one by one. A reviewer label at the start of a quoted line (`W1.`) is
ignored.

- Quote the reviewer's words exactly; shorten by cutting with an ellipsis, never by paraphrase inside quote marks.
- Quotes from the venue's guideline come from the page as fetched, saved as `guideline.txt` with its address and date.
- One audit verified 18 quotations character by character. Run the script on every build anyway: texts move.

## Absolute words and claims of scope

Absolute claims ("nothing", "first", "every", "fixed in advance", "same corpus") must survive a search of your own
paper for counterexamples:

- an absolute claim of independence was struck because the paper's own appendix described a procedure that
  contradicted it; the replacement rested on a checkable count with line numbers.
- "fixed in advance" was struck because a stopping rule was added during the run.
- "the first model" became "the first [modality] model" because the paper cites counterexamples.
- A venue attribution the author insisted on was checked against the bibliography and found to be a different
  journal; the reply used a broader phrase that kept the point and was true.

Before sending, search the paper for every sentence that limits each claim the reply makes.

## Counts and comparison sets

- Name the comparison set with every count: "[N] compared methods ([the kinds of method])". Check whether the count
  includes your own method ("is it N methods or N minus 1?" was the author's question); the fix was "[N] methods
  (ours and [N minus 1] others)".
- State what a fraction counts (tasks, folds, pairs) whenever one appears.
- Qualify aggregate claims as aggregate ("in aggregate", "by mean rank").
